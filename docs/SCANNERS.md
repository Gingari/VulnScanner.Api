# Как добавить анализатор

[← README](../README.md)

Новый CLI-анализатор подключается через адаптер C# и Dockerfile. Добавление произвольной команды через HTTP не поддерживается: клиент не должен получать возможность запускать программы на сервере.

## Контракт

Интерфейс `Analyzer.Scanners.ICodeScanner`:

```csharp
using Api.Models;

namespace Analyzer.Scanners;

public interface ICodeScanner
{
    Task<ScanResult> ScanAsync(
        string repositoryPath,
        CancellationToken cancellationToken);
}
```

На вход поступает **локальная папка уже скачанного репозитория**, не URL. Адаптер не должен повторно клонировать репозиторий или удалять общую папку. Оркестратор вызывает все зарегистрированные анализаторы и сам управляет общей папкой.

## Пошаговое подключение

### 1. Выбрать CLI и проверить контракт

До написания адаптера проверьте инструмент вручную:

- какие языки и manifest/lock-файлы он поддерживает;
- требуется ли сеть, отдельная база правил или кеш;
- умеет ли выдавать JSON в файл;
- какие exit codes означают находки, а какие — сбой;
- может ли запускать плагины, скрипты или загружать конфигурацию из репозитория;
- способен ли записывать реальные секреты в отчёт или диагностический вывод.

Не включайте сборку, установку зависимостей или исполнение проекта для получения результата анализа.

### 2. Реализовать адаптер

Пример структуры:

```text
Analyzer/Scanners/
└── CustomScanner/
    ├── CustomScanner.cs
    └── CustomReport.cs
```

Адаптер должен:

1. Получить `IProcessRunner` через конструктор.
2. Создать уникальную папку отчёта вне репозитория.
3. Передать собственную доверенную конфигурацию и явные аргументы.
4. Запустить CLI с конечным тайм-аутом и переданным токеном.
5. Проверить код завершения и наличие отчёта.
6. Ограничить размер перед чтением, разобрать JSON и преобразовать находки.
7. Удалить свои временные файлы в `finally`.
8. Пропустить `OperationCanceledException` наружу — не превращать отмену в пустой успешный результат.

Общий способ запуска процесса:

```csharp
var execution = await _processRunner.RunAsync(
    executable: "custom-scanner",
    arguments: arguments,
    workingDirectory: reportDirectory,
    timeout: TimeSpan.FromMinutes(2),
    cancellationToken: cancellationToken);
```

`arguments`, `reportDirectory` и обработка exit code зависят от выбранного инструмента. Имя программы и разрешённые флаги задаёт приложение, не запрос API. Shell-команду из пользовательского ввода собирать нельзя.

### 3. Вернуть единую модель

```csharp
return new ScanResult
{
    TotalFindings = findings.Count,
    Findings = findings
};
```

Каждый `FindingVuln` содержит:

```csharp
new FindingVuln
{
    Scanner = "custom-scanner",
    Name = "Rule or vulnerability identifier",
    Severity = "High",
    FilePath = "relative/path/to/file",
    Description = "Safe description without secret values"
};
```

Не копируйте в ответ значения секретов, полный исходный код, чувствительные URL или произвольные диагностические дампы. Если инструмент не оценивает severity, явно опишите свою политику, не выдавая её за оценку инструмента.

### 4. Зарегистрировать в DI

В `Program.cs`:

```csharp
builder.Services.AddSingleton<ICodeScanner, CustomScanner>();
```

Существующие регистрации не удаляйте, если нужны все анализаторы. Порядок регистрации определяет последовательность запуска в `IEnumerable<ICodeScanner>`.

Изменять контроллеры, очередь и фоновый сервис не требуется.

**Singleton должен быть потокобезопасным.** Несколько задач могут одновременно вызвать один объект адаптера. Не храните текущий ID, путь репозитория, отчёт или результат в общих полях. Для непараллельного CLI или общего кеша используйте локальную синхронизацию, как у Trivy. Такая синхронизация действует только внутри одного процесса API, не между контейнерами.

### 5. Установить инструмент в Dockerfile

Добавьте скачивание/установку в build-stage и копирование бинарника в runtime-stage. Зафиксируйте версию и используйте бинарник Linux нужной архитектуры, а не Windows `.exe`.

Перед сдачей проверьте источник, контрольные суммы или подписи релиза. Текущий предложенный Dockerfile загружает архивы по HTTPS, но сам по себе не проверяет их криптографическую подпись или checksum.

Если у инструмента есть дополнительные библиотеки, интерпретатор или правила, их также нужно включить в runtime-образ. Не запускайте установку при каждом сканировании.

Если версия задаётся через Compose:

```yaml
build:
  args:
    CUSTOM_SCANNER_VERSION: ${CUSTOM_SCANNER_VERSION:?Set the version}
```

Обновите `.env.example` и документацию. Для локальной разработки CLI должен находиться в `PATH` или нужен отдельный конфигурируемый путь к executable.

### 6. Написать тесты

Через подмену `IProcessRunner` проверьте:

- пустой успешный отчёт;
- одну и несколько находок;
- преобразование severity и файлов;
- отсутствие секретных значений в сериализованном результате;
- error exit code, отсутствующий или невалидный JSON;
- превышение размера отчёта;
- отмену и очистку файлов;
- код завершения «находки», если он отличается от нуля.

У оркестратора проверьте объединение результатов с существующими анализаторами. Отдельный ручной smoke-тест должен запускать настоящий CLI на безопасном примере с ожидаемой находкой.

### 7. Пересобрать и проверить

```powershell
dotnet test ./tests/VulnScanner.Tests/VulnScanner.Tests.csproj
docker compose up --build -d
docker compose logs -f api
```

Через Swagger запустите задачу. Логи должны показать начало и завершение нового анализатора. Само отсутствие ошибок или ноль находок ещё не доказывает, что инструмент действительно распознал входные файлы.

## Как отключить анализатор

Сейчас универсальный `Enabled`-флаг и REST-эндпоинт управления анализаторами не реализованы. Чтобы исключить адаптер, удалите его регистрацию `AddSingleton<ICodeScanner, ...>()` и пересоберите приложение. При необходимости отдельно уберите бинарник из образа.

## Поведение ошибок

Текущий оркестратор прекращает задачу при первой ошибке анализатора. Следующие инструменты не запускаются; накопленные частичные находки не сохраняются как успешный результат. Если понадобятся частичные результаты, потребуется отдельная модель статуса каждого анализатора и изменение политики выполнения — это не просто добавление `catch` с игнорированием ошибки.
