# Vulnerability Tracker API

REST API для регистрации уязвимостей и фонового сканирования публичных Git-репозиториев.

Используются:
- **Gitleaks** — поиск потенциальных секретов.
- **Trivy** — поиск известных уязвимостей зависимостей.

## Быстрый запуск

Нужен только Docker.

Команда для Ubuntu:

```bash
docker run -d `
  --name vulnscanner `
  --init `
  -p 127.0.0.1:8080:8080 `
  --memory=3g `
  --cpus=2 `
  -e ASPNETCORE_ENVIRONMENT=Development `
  -e Repositories__AllowedHosts__0=github.com `
  -e Repositories__AllowedHosts__1=gitlab.com `
  -e Repositories__AllowedHosts__2=bitbucket.org `
  gingari/vulnscanner-api:1.0.0
```

Docker автоматически скачает образ, если его нет локально.

**Swagger:** http://localhost:8080/swagger

Первый анализ может занять больше времени: Trivy загружает базу уязвимостей.

Логи:

```bash
docker logs -f vulnscanner
```

Остановка и удаление:

```bash
docker stop vulnscanner
docker rm vulnscanner
```

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/v1/vulnerabilities` | Добавить уязвимость |
| GET | `/v1/vulnerabilities/{id}` | Получить уязвимость |
| POST | `/v1/scans` | Запустить сканирование |
| GET | `/v1/scans/{id}` | Получить статус и результат |
| POST | `/v1/scans/{id}/cancel` | Запросить отмену |

### Создание уязвимости

```json
{
  "name": "SQL Injection",
  "severity": "Critical"
}
```

Критичность: `Low`, `Medium`, `High`, `Critical`.

Сервер назначает ID и дату. Ответ — `201 Created` с ID.

### Запуск сканирования

```json
{
  "repositoryUrl": "https://github.com/Gingari/VulnScanner.Api"
}
```

Ответ — `202 Accepted` с ID задачи. Результат запрашивается через GET.

Статусы: `Queued`, `Running`, `Completed`, `Failed`,
`CancellationRequested`, `Cancelled`.

Отмена возвращает ID, время и признак принятия запроса.
Фактическая остановка подтверждается статусом `Cancelled`.

## Настройки запуска

Настройки можно передавать дополнительными аргументами `-e`
перед именем образа:

```bash
-e Scanning__MaxParallelScans=2 `
-e Scanning__QueueCapacity=10 `
-e Repositories__CloneTimeoutSeconds=120 `
```

По умолчанию: 2 выполняющиеся задачи, 10 мест в очереди,
120 секунд на клонирование.

Для другого внешнего порта замените:

```text
-p 127.0.0.1:9090:8080
```

Изменение параметров требует пересоздания контейнера.

## Хранение и выполнение

Все уязвимости, задачи и результаты хранятся в памяти
и исчезают после перезапуска.

Репозиторий скачивается один раз. Анализаторы выполняются
последовательно, результаты объединяются. Временные файлы
находятся в `/work/tmp` и удаляются после обработки.

Кеш Trivy находится в `/work/cache`. Для сохранения между
удалениями контейнера можно добавить при запуске:

```text
-v vulnscanner-trivy-cache:/work/cache
```

Ручной реестр уязвимостей и результаты сканирования независимы:
найденные проблемы автоматически в реестр не добавляются.

## Ошибки

- `400` — некорректный запрос или запрещённый URL.
- `404` — объект не найден.
- `409` — задача уже завершена и не может быть отменена.
- `429` — очередь заполнена.
- `500` — непредвиденная ошибка API.

Ошибка фонового анализа сохраняется в задаче со статусом `Failed`.

## Тесты

Для запуска из исходников нужен .NET SDK 10:

```bash
dotnet test ./tests/VulnScanner.Tests/VulnScanner.Tests.csproj
```

Тесты используют подмены внешних процессов, поэтому отдельная
установка анализаторов не требуется.

## Добавление анализатора

1. Реализовать `ICodeScanner`.
2. Запустить CLI через `IProcessRunner`, передав токен отмены.
3. Преобразовать отчёт в `ScanResult`.
4. Зарегистрировать адаптер в `Program.cs`:

```csharp
builder.Services.AddSingleton<ICodeScanner, CustomScanner>();
```

5. Добавить инструмент в Dockerfile, написать тесты и пересобрать образ.

Оркестратор автоматически получит новый адаптер через
`IEnumerable<ICodeScanner>`.

## Ограничения

- Поддерживаются публичные HTTPS-репозитории разрешённых хостов.
- Проверяются текущие файлы, без полной истории Git и submodules.
- Код репозитория не собирается и не запускается.
- Ноль находок не гарантирует безопасность: анализатор должен
  распознать поддерживаемые файлы.
- При ошибке одного анализатора вся задача получает `Failed`.
- API и анализаторы работают в одном контейнере.
- Аутентификация не реализована.
